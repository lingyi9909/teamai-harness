# Java coding style

Match the repository's formatter, naming, package, import, nullability, exception, logging, immutability, and dependency-injection conventions. Prefer clear domain names, small cohesive methods, explicit ownership, and constructor injection when it matches the codebase.

Do not add utility abstractions, reflection, global mutable state, unchecked casts, catch-all exception swallowing, or annotation-heavy shortcuts without a concrete repository need. Preserve public contracts unless the task explicitly changes them. Avoid comments that merely restate code; document non-obvious invariants and decisions instead.
