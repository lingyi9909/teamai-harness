## 功能与分工

| 功能 | 核心仓库 `codea-harness` 的工作 | 本仓库的协同材料 |
|---|---|---|
| Java / Spring 识别 | this/super、继承、有限重载和明确注入条件；无法确定时给出缺口 | 不重复实现解析器 |
| 每次 Review 自动调用链 | 按本次源码生成临时关系，保留真实范围选择 | 不让人员维护索引或每次刷新保存链 |
| MyBatis | Mapper/XML/参数/result/include 关联，不执行 SQL | 公共使用说明可由内网补充 |
| Dubbo | 明确契约、group/version 与已获准依赖源码边界 | 缺 Provider 源码不猜运行路由 |
| 有界代码上下文 | 按变更及范围按需找上下游，预算与不确定性可见 | 不创建持久代码索引或图服务 |
| 证据与报告 | 规则及源码引用复核、反证、去重、未完成项与研发转述 | 轻量入口只转交已安装流程 |
| 业务知识读取 | 显式来源、必读规则、路径边界、缺失/冲突/变动和证据校验 | 知识归属、引用和资料模板 |
| TeamAI / 内网协同 | 核心能力声明、版本兼容、知识绑定及旧项目兼容 | 本仓库资源、复制方式和文件归属 |

不新增 LSP、JDT、完整 OpenCodeReview 集成、本地持久索引、图查询、快照系统、发布保障平台。保留已有 ChangeSet、认证、freshness、运行记录和安装/升级机制；“本版不做快照”不等于删除旧版的必要机制。

## 核心与入口的最小对接要求

- 核心公布实际支持的版本/能力，以及本地知识读取入口。旧版不支持时明确显示业务检查尚未启用，不通过 Skill 冒充实现。
- 知识来源限已声明的本地项目根/团队资料根，校验最终路径、适用性、大小和引用版本。不得将知识根变成任意代码 workspace 或网络访问入口。
- 正式规则有稳定 ID、适用范围、有效状态和来源；参考资料与经验不能自动升级为强制规则。
- 核心记录实际引用，必需知识未完成不出无保留通过；已有证据/范围门禁不能降级。
- 安装、升级和 TeamAI 同步遵守单一文件归属。新增项目知识绑定若落在核心目录中，必须登记为应保留的项目状态。

## 验收重点

在同一已批准版本组合上验证：完整/定向 Review、调用链自动变化但不改保存链、关键解析反例、业务规则有效/缺失/冲突/运行中变化、旧项目无知识绑定、TeamAI 不可用但资料已就绪、安装组件缺失及同名冲突。

对已有核心计划要求的真实模型样例继续执行；预置 proposal 不代替真实 Reviewer。技术缺陷、业务规则违反与资料缺口分别报告；完整零问题只给简短结论。

必须验证 TeamAI 同步实际保留核心文件、核心升级实际保留知识和项目状态。验证全过程不访问外网、不自动下载依赖，不要求登录全链路平台或查询日志。未具备真实内网环境的部分标记未执行。
