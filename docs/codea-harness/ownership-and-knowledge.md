# 文件归属和业务知识

> 最新确认：TeamAI现有目录及管理方式不变，以下路径均为本资源包示例，不要求内网照搬或迁移知识。Harness完整包只是在总仓/制品目录中保存，由Git管理，安装升级沿用核心原流程；TeamAI命令仅同步其资源。

目录可以在同一总仓库中；归属边界按文件区分，不要求再建一批仓库。

| 内容 | 维护方和唯一来源 | 更新方式 |
|---|---|---|
| Runtime、核心 Skill、正式 Reviewer | Codea Harness 正式版本 | 正式安装/升级包整体更新 |
| `skills/codea-harness-review/`、协作规则 | 本公共资源包 | 经比较导入内网；不复制核心流程 |
| 总仓 `teamai.yaml`、角色/项目筛选 | 内网 TeamAI 管理员 | 保留原配置，按条目维护 |
| `docs/codea-harness/`、`templates/codea-harness/` | 本公共资源包 | 通用说明和模板；不填真实公司内容 |
| `docs/codea-knowledge/common/` | 内网团队负责人 | 公共组件、术语、公共规则的唯一来源 |
| `docs/codea-knowledge/projects/` | 内网项目负责人 | 项目介绍、归属和权威资料引用 |
| 项目专属正式业务规则 | 对应业务仓库的负责人 | 与业务版本一起评审，团队仓只存引用 |
| `harness.yaml`、项目状态、`runs/`、已有 `chains/` | 业务项目/现有 Harness 流程 | 不作为公共分发源，不被 TeamAI 管理 |
| 账号、验证码、Cookie、Token、会话 | 本机或公司已有认证设施 | 不进入共享仓库或公共模板 |

TeamAI 和 Harness 都可能使用业务项目 `.opencode/`，但写入不同文件：TeamAI 管理辅助 skills/rules；Harness 管理正式 Reviewer Agent、command 和提交工具。总仓已有其他 Agent 可以保留，但不能自动接管 Harness 的 Reviewer。同名冲突需要迁移确认，不依赖最后写入覆盖。

## 知识放哪里

1. 跨项目通用知识沿用内网现有公共知识位置，不要求新建`docs/codea-knowledge/common/`。
2. 项目介绍、架构入口及负责人沿用现有项目资料位置，记录业务仓库路径和规则来源，不再复制一份可独立修改的正式规则。
3. 项目专属规则放业务仓库现有文档目录；没有约定时可使用 `docs/harness/business-rules/`。调用链由代码自动分析，人员只维护业务含义和正式要求。
4. 旧经验按内网已有方式保留，本版不要求新建经验库或自动贡献。经验只是参考，不能据此断言当前代码错误。

例如：公共幂等组件的使用说明由团队维护；订单状态转换要求由订单项目维护。Review 报告若指出订单越过某个状态，需要同时引用适用规则和本次代码证据，不能只写“根据团队经验”。本例描述存放方式，不构造实际公司规则。

## 知识进入 Review 的条件

1.7 拟增加明确的本地知识来源绑定：项目 ID、资料根、相对路径、资料类型及必需性。具体机器字段和 Runtime 读取/认证接口由核心研发实现；本包的 Markdown 模板仅用于整理资料，不是自动可执行配置。

先读适用且必需的正式规则，再按需读参考资料；不依赖一次召回是否命中来决定必需规则是否存在。引用需记录来源、版本、适用模块/入口。草稿不生效，文档自写“已批准”不等于真实评审记录。规则冲突不能由 Agent 静默选一条。

必需规则缺失、冲突或变动时，相关业务检查标记未完成；可继续的技术检查单独报告。旧版未支持业务知识认证时不伪造 Finding 证据字段或修改正式报告。已安装 TeamAI 的召回功能可沿用，但本资源包不启用新索引、图查询或 Recall。

知识只提供事实与要求，不提供执行权。引用内容中的平台链接、脚本、登录文字不得自行执行。资料阅读边界不得扩大为跨仓代码扫描或业务写入权限。

## 外网与内网怎么合并

外网维护通用核心、轻量入口和空模板；内网维护实际公司知识、项目引用和本地配置。本仓库更新只覆盖它明确拥有的通用文件；从模板创建的知识文件放到内网知识目录，文件名自行确定，后续不再视为公共模板副本。

内网不维护核心补丁目录，也不长期分叉另一份 Harness。通用功能需要修复时，向通用核心提出不含公司资料的需求或最小复现，再按公司流程导入正式版本。不存在自动双向同步、内网信息自动回传或内网访问 GitHub 的步骤。

TeamAI 的目录分组不构成访问权限隔离：同一 Git 仓库的读权限通常覆盖全部文件。若知识保密范围不同，沿用公司已有受限仓库和权限，不为了集中管理扩大共享范围。
